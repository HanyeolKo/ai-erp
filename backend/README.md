# Backend integration tests

Run the PostgreSQL and Redis integration suite with `./gradlew integrationTest` (or `gradlew.bat integrationTest` on Windows). It resolves the pinned test binaries from Maven Central and starts temporary native processes bound to `127.0.0.1`; no Docker daemon or system database installation is needed. The PostgreSQL server binary is 18.6.0, matching the production release. The fixture sets `lc_messages=C` so database error assertions remain consistent on hosts with a different OS locale; platform filesystem behavior can still differ between Windows and Linux. Production PostgreSQL configuration and Flyway migrations remain unchanged. The fixture removes temporary database data and stops its processes after each test class.

The Redis fixture uses `com.github.codemonstur:embedded-redis:1.4.3` because the application contexts require a live Spring Session Redis backend. That artifact bundles Redis 5.0.14.1 on Windows x64 and Redis 6.2.6-v5 on Linux x64, while production uses Redis 8.2.9. The integration tests verify readiness, a Redis PING, and a Spring Session save/load round trip. On Windows, the fixture starts the bundled server with loopback/ephemeral CLI options and no config file; this keeps Redis 5's INFO paths readable by Spring Data Redis. These bundled versions do not establish Redis 8.2.9 feature parity; production image/runtime validation remains responsible for version-specific behavior.

The full CI workflow still uses Docker for Compose configuration checks and building the application image; only the `integrationTest` task uses native test processes.
