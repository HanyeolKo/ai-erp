# Recovery playbook

Restore context from `harness/HARNESS.md`, the spec, current state, and the latest journal entries.
If references, provider parity, or vendor hashes fail, stop dependent work and repair canonical sources first.
Run provider-path preflight before reprojecting wrappers or new projections.
If a specialist or implementer cannot be invoked, preserve the unresolved prerequisite and do not claim review completion.
For high/complex code work, recover the parent contract revision, selected model and reason, invocation evidence, context manifest/budget, output budget, fork/reuse choice, usage availability, `MODEL-ESCALATION.md`, attempt count, implementation result, and upper independent-review state before resuming. Bounded low/standard work recovers its compact `TASK-RECORD.md`. Escalation is parent-owned Luna/high -> Terra/medium -> Sol/medium; a Sol-ceiling failure returns for Astra self-review and never creates an Astra executor.
If a plan or contract fails review, return bounded findings for one constrained revision and record a stable defect key.
For release evidence, distinguish release-ready from deployed, preserve prior release and active-state pointers, and mark unresolved recovery or exit 2 as `operator-action-required`.
After three attempts, report the exact blocker and a concrete next action.
Never erase failed evidence, weaken evaluator criteria, or add approval gates to avoid surfacing a failure.

If a required external prerequisite is missing or unknown, stop the affected task before dependent edits or execution and return a BLOCKER-REPORT to the parent. At most three total attempts apply only to repairable implementation defects, including the initial attempt and any escalation. External blockers stop immediately, consume no retry attempt, and cannot authorize model escalation or a model sweep. Do not retry an unchanged external blocker. Resume checks require target-specific evidence, current affected revisions, applicable policy reviews, and parent assignment confirmation.
