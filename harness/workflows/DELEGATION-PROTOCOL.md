# Delegation protocol

1. Parent owns acceptance, architecture, scope, permissions, and actual dispatch. Router bounds the assignment without expanding it.
2. A high/complex assignment must identify task, increment or maintenance applicability, plan/contract revisions, sender, recipient, source/base Git evidence, prerequisites, scope, exclusions, interfaces, outputs, acceptance, checks, model/effort and selection reason/evidence, reviewer, permissions, and stop conditions. It also declares the input context manifest/budget, output budget, fork/reuse choice, and provider usage availability. A bounded low/standard task may carry its minimal assignment, acknowledgement, result, checks, blockers, and parent disposition in one `TASK-RECORD.md` or inline task record.
3. Recipient acknowledges matching task/revisions and scope before changes. Missing, stale, or conflicting prerequisites return `blocked`.
4. States are `assigned -> acknowledged -> running -> ready-for-review -> reviewed -> complete`; `blocked` and `changes-requested` return to the parent with evidence.
5. Workers return changed paths, artifacts, acceptance mapping, actual checks and exits, deviations, and risks. Workers never self-approve, re-delegate, route, or change scope.
6. A failed required review returns `changes-requested`; low/standard work may move to parent acceptance after applicable checks, while high-risk work needs an independent Astra/high pass plus parent acceptance.
7. Parent applies `harness/policies/VERIFICATION.json` and requests only the applicable review. Retry only the affected bounded work for at most three total attempts including the initial attempt and any escalation, preserving failed evidence and revising stale assignments. Renaming a task or revision never resets the count.
7a. Model escalation is parent-owned and recorded in `harness/templates/MODEL-ESCALATION.md`: Luna/high -> Terra/medium -> Sol/medium, never Astra execution. The ceiling is three total attempts including the initial attempt and escalation; a Sol-ceiling failure returns to the Astra orchestrator for self-review. Workers cannot self-escalate.
7b. Escalate only for a demonstrated capability/comprehension failure against a complete, clear contract. Clarify ambiguous/incomplete assignments and use same-model correction for ordinary repairable defects; external prerequisites or quota/capacity blockers stop without escalation.
8. Release-manager may prepare or execute only the parent-authorized release scope; source, test, config, routing, and verdict changes return to the parent.
9. Assignments declare external dependency mode and target-specific readiness. Unknown is never ready; missing required API, account, permission, OAuth, or managed setup stops dependent work before edits or execution and returns `BLOCKER-REPORT` to the parent.
10. Acknowledgement does not waive an external blocker. Goal-mode continuation cannot override it, and unchanged external state is not retried under the three-total-attempt ceiling. Resume requires new evidence, current affected revisions and independent reviews, and parent assignment confirmation.
11. Missing external setup or quota/capacity stops immediately, consumes no attempt, and never authorizes escalation or a model sweep; only an already-approved same-cost alternative may be assigned explicitly by the parent.
12. Default to one active worker; use at most two only for explicitly disjoint useful work. New workers use `fork_turns=none` or equivalent minimal context; full-history fork requires parent justification. Reuse only the same bounded context; scope changes require a fresh minimal assignment. Do not rerun passed checks without a change or unresolved concern. Default return target is 250 words plus evidence paths.
