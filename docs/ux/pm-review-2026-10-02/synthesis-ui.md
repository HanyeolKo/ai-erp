## Current evidence and constraints
현재 제품은 프로젝트 안의 `계획`과 시각 단위 `일정`을 별도로 관리한다. 계획에는 `EPIC/TOPIC/TASK/MILESTONE`, TASK 여섯 상태 `BACKLOG/READY/IN_PROGRESS/BLOCKED/DONE/CANCELLED`, 날짜·담당자·선행 관계와 변경 이력이 있다. 일정에는 `DRAFT/CONFIRMED/CANCELLED`, 참여자별 확인, Calendar 투영, 사용자 정의 속성, 개인·공유 저장 보기가 있다. 이 투자가 새 기본 화면 때문에 삭제되거나 권한이 약화되어서는 안 된다.
네 상태 축은 항상 독립 표시한다. ① TASK 상태, ② 일정 상태, ③ 현재 사용자의 참여 확인 상태, ④ Calendar 투영 상태를 별도 레이블과 설명으로 보여 준다. TASK를 완료해도 일정·참여 확인·Calendar 상태는 바뀌지 않고, 시간 블록이 끝나도 TASK는 완료되지 않는다. 링크 생성도 초대, 날짜 복사, 자동 완료, Google 권한을 발생시키지 않는다.
권한은 현재 계약을 정확히 유지한다. 계획 편집은 `MANAGER/MEMBER` 공유, `VIEWER` 읽기 전용이며 일정 편집은 `MANAGER-all/MEMBER-own-created/VIEWER-none`이다. 일정의 **기본 TASK 지정·변경·해제·재지정**은 일정 자체의 의미를 바꾸므로 해당 일정 쓰기 권한, 즉 MANAGER 또는 `createdBy`가 현재 MEMBER인 경우에만 가능하다. **관련 TASK/MILESTONE 추가·해제**는 보조 링크이며 계획 영역 쓰기 권한과 같은 프로젝트 대상 읽기 권한을 요구한다. 선택기는 `기본 TASK`와 `관련 항목`을 명시해 섞지 않고, 접근 불가·다른 프로젝트 대상은 검색 결과와 직접 ID 제출 모두 서버에서 거부한다. 모든 진입점은 링크의 `rowVersion` 같은 revision을 보내 409 시 최신 링크와 보존된 초안을 비교한 뒤 재시도하며 자동 덮어쓰지 않는다. 다른 사람이 만든 일정을 읽을 수 있고 그 TASK 담당자인 MEMBER도 보조 관련 링크만 계획 권한으로 추가할 수 있으며, 기본 TASK를 바꾸거나 일정·참석자를 편집할 수 없다. TASK 배정이나 링크는 Drive 권한을 주지 않는다.
계획 날짜는 시간대 없는 `date-only` 값이다. 일정은 시간대와 실제 instant를 유지한다. 교차 프로젝트 `내 작업`의 “오늘”과 기한 경계는 사용자 표시 시간대에서 계산하되, 저장된 계획 날짜를 UTC나 일정 시작일로 자동 변환하지 않는다. 자정·일광절약시간 경계에서도 “TASK 마감일”과 “일정 현지 시각”을 나란히 보여 주고 불일치는 관찰로만 표시한다.

실제로 적용한 고정 지침은 `ai-erp-frontend-design`, `ai-erp-ui-ux-pro-max`, `ai-erp-web-design-guidelines`이다. 읽기/편집 위계, 점진적 필터, 상태 배지와 조작 제어의 의미 분리, URL 상태, 390px 재배치, 키보드·오류 초점·live feedback을 선택했다. ERP와 무관한 hero/video/CTA, 생성 팔레트·글꼴은 배제했다. 명령·결과·SHA-256·선택/배제 근거는 `tmp/pm-review-2026-10-02/guidance/ui-r2-guidance-evidence.md`에 있다.
## 정보 구조와 기본·고급 경계
전역 1차 탐색은 `내 작업`, `프로젝트`, `알림`이다. 프로젝트 안 1차 탐색은 `개요`, `작업`, `일정`, `파일`, `설정`이다. `내 작업`은 권한 있는 모든 프로젝트의 개인 실행면이며, 프로젝트 전환 없이 필터를 유지한다. 프로젝트 `개요`는 합의 결과와 위험을, `작업`은 기본 TASK 목록을, `일정`은 연결 여부와 무관한 시간 약속을 담당한다.

기본 화면은 빈번한 판단만 노출한다. TASK 기본 목록은 제목, 프로젝트, 전용 우선순위, 상태, 마감, 차단 이유, 연결된 다음 시간만 보이고 행 전체가 상세 진입점이다. `고급 계획 보기`는 기존 여섯 보기 `로드맵/계층/작업/보드/Milestone/월간`과 종류·상태·담당자·날짜·레이블 필터, 정렬·그룹, 50건 페이지를 그대로 연다. `고급 일정 관리`는 현재의 개인·공유 저장 보기, 사용자 정의 속성, 필터·정렬·그룹·범례를 유지한다. 최소 기본값은 기존 속성 값, 보관된 옵션, 저장 보기, URL 필터, 데이터 또는 편집권을 지우지 않는다.

프로젝트 설정은 단계형이지만 이름 외 항목은 레거시 프로젝트를 막지 않는다. 필수는 `프로젝트 이름` 하나다. 기본 권장 항목은 `목적`, `성공 기준`, `책임 관리자`, `목표 기간`이며 비어 있으면 “아직 정의하지 않음”으로 보인다. 선택 항목은 `수동 건강 상태`, 이유와 기준일이다. 건강 상태는 저장된 관리자 판단이고, 기한 지남·차단·날짜 불일치 같은 시스템 관찰과 섞지 않는다. 기존 프로젝트는 재입력 없이 열리고 개요에서 누락 항목을 보완할 수 있다.

TASK 생성의 필수 항목은 `제목`과 `상태` 기본값 `BACKLOG`이다. 기본 권장 항목은 담당자, 전용 우선순위, 시작/종료 목표일, 마감일, 완료 기준이다. 선택 항목은 설명, 상위 항목, 레이블, 선행 TASK, 보조 마일스톤, 여러 시간 블록, 여러 파일 참조이다. 빠른 생성은 필수만 받고 상세에서 나머지를 보완한다. 일정 생성은 기존 제목·시작·종료를 유지하고, 선택적으로 같은 프로젝트의 기본 TASK 하나와 보조 TASK/MILESTONE 여러 개를 연결한다. 일반 회의는 기본 TASK 없이 저장할 수 있다.
## 대표 전후 흐름 5개
1. **프로젝트 시작** — 이전에는 이름 입력 후 일정 초대로 이동해 합의 결과가 남지 않았다. 이후 MANAGER는 이름으로 즉시 만들고, 같은 화면의 “운영 기준 추가”에서 목적·성공 기준·책임·목표 기간을 선택적으로 입력한다. 건너뛰면 개요에 보완 안내가 남으며 기존 기능은 즉시 사용 가능하다. 저장 충돌 시 최신 값과 내 초안을 비교하고 재확인한다.
2. **여러 프로젝트의 오늘 일 찾기** — 이전에는 각 프로젝트의 계획과 일정을 순회했다. 이후 구성원은 `내 작업 > 오늘`에서 서버가 권한별로 거른 열린 TASK를 본다. 기본 정렬은 `차단/기한 위험 → 전용 우선순위 → 마감 → 제목`이고 프로젝트·상태·담당자(나/미배정)·기한 범위·연결 시간 유무를 필터한다. 권한 없는 프로젝트 결과와 집계는 서버에서 제외하며, 필터 결과가 0이면 필터 해제와 “프로젝트에서 TASK 만들기” 권한별 동작을 제시한다.
3. **TASK에 실행 시간과 자료 연결** — TASK 상세의 `시간`에서 “시간 확보”는 새 일정 초안을 열고 날짜를 자동 복사하지 않는다. 기존 일정 연결은 `기본 TASK로 지정`과 `관련 항목으로 연결`을 분리한다. 전자는 일정 쓰기 권한이 있을 때만 보이고, 후자는 계획 쓰기 권한으로 읽을 수 있는 같은 프로젝트 일정에만 가능하다. 타인 생성 일정을 읽는 TASK 담당 MEMBER는 보조 연결만 할 수 있다. 외부 프로젝트·접근 불가 대상은 거부하며 충돌 시 초안을 보존한다. 파일은 기존 참조를 연결하거나 권한이 있으면 추가하고, 실제 열기 상태는 별도 기록한다.
4. **관리자 지연·주간 검토** — 이전에는 기한 지남과 차단 수는 보이지만 다음 영향과 조치를 한 흐름에서 설명하지 못했다. 이후 `개요 > 위험`은 저장 사실(상태·날짜·선행·링크)과 파생 관찰(기한 지남, 날짜 없음, 차단, TASK 날짜와 연결 일정 시간 불일치, 마일스톤 증거 누락)을 문구와 기준 시각과 함께 분리한다. MANAGER는 `주간 검토`에서 프로젝트별 필터 후 이유를 펼치고 TASK·마일스톤 상세로 이동한다. 시스템은 자동 재계산, 임계 경로, 용량 결론을 제시하지 않는다.
5. **마일스톤 결정** — 이전에는 후속 TASK 수가 마일스톤 영향처럼 보였다. 이후 선택적 `준비 기준`마다 설명, 충족 여부, 연결 TASK/파일을 두고 관리자가 최종 `준비/미준비/예외 승인` 결정, 근거, 기준일을 기록한다. 완료 TASK 수만으로 준비를 선언하지 않는다. 증거가 삭제·취소되면 “필수 증거 누락” 관찰을 만들고, 원래 이력과 결정은 보존한다.

## 상태, 복구와 권한 피드백
모든 주요 화면은 같은 상태 문법을 쓴다. 초기에는 마지막 선택 필터와 기준일을 표시한다. 로딩은 제목·탐색을 유지하고 목록 영역에 진행 상태와 `aria-busy`를 둔다. 빈 상태는 “데이터 없음”과 “현재 필터 결과 없음”을 구분한다. 부분 성공은 불러온 카드와 함께 실패한 영역만 경고하고 재시도한다. 전체 오류는 입력값을 보존하고 재시도·상위 화면 이동을 제공한다. 저장 중에는 해당 저장 동작만 잠그고 `저장 중`을 알린다. 성공은 `role=status`로 항목명과 저장 범위를 말한다.

검증 오류는 필드 가까이에 원인과 수정법을 연결한다. `403/revoked`는 보호 데이터와 편집 동작을 잠그고 “접근 상태 다시 확인”을 제공한다. 링크 대상이 접근 불가·다른 프로젝트면 선택을 확정하지 않고 이유를 알린다. `409/conflict`는 최신 링크/값, 유지된 내 초안, 겹친 필드를 구분해 다시 불러오기·검토 후 저장·취소를 제공하며 자동 덮어쓰지 않는다. 응답 단절은 `저장 여부 확인 중`으로 두고 같은 request ID를 조회한다. Drive 메타데이터가 보여도 열기 권한을 추정하지 않으며 `unknownDriveaccess`는 “아직 확인하지 않음”, 거부는 “Google에서 접근 권한 확인”으로 표시한다.

일정 취소, TASK 취소, 링크 제거, Drive 참조 제거는 서로 독립이다. 필수 마일스톤 증거가 사라지면 삭제를 막는 대신 영향 경고와 명시적 계속 여부를 권한자에게 묻고 감사 이력을 남기는 방향을 구현 계약에서 결정한다. 비활성 기능은 기존 운영 화면으로 돌아가되 새 링크·감사 기록을 삭제하지 않는다.
## 반응형·키보드·접근성
390px에서는 전역 탐색을 메뉴 버튼으로 접고 화면 제목, 위험 요약, 주요 동작 하나를 먼저 둔다. 표는 의미 있는 카드로 바꾸되 프로젝트·상태·마감·차단·다음 시간 라벨을 숨기지 않는다. 필터는 하단 시트가 아니라 문서 흐름의 펼침 영역으로 제공해 확대와 키보드에 견딘다. TASK 상세은 `기본/시간/파일/마일스톤/고급`의 세로 섹션이며 고정 폭이나 가로 드래그를 요구하지 않는다. 44px 수준의 터치 영역, 200% 확대에서 정보 손실 없는 재배치, 오류 문구의 줄바꿈을 구현 검증 대상으로 둔다.

키보드 순서는 전역 탐색 → 제목/주요 동작 → 필터 → 요약 → 목록 → 페이지 이동이다. `Enter/Space`로 행 상세와 펼침을 열고, 빠른 편집은 `Escape`로 취소하며 초점을 원래 제어로 돌린다. 모달은 제목으로 이름을 갖고 초점을 가두며 닫은 뒤 호출 버튼으로 복귀한다. 저장·오류·충돌은 `status/alert`로 한 번만 읽고 색만으로 상태를 구분하지 않는다. 아이콘에는 텍스트 이름, 상태 배지에는 기계 토큰과 한국어 의미, 날짜·시간에는 시간대 설명을 제공한다. 비활성 버튼은 사유를 인접 문구로 설명한다.
## Decisions and acceptance criteria
설계 이유는 세 가지다. 프로젝트/TASK 중심 기본 경로는 분리된 정보의 탐색 비용을 낮춘다. 기존 기능을 고급 진입점에 보존하면 단계적 도입 중 데이터·권리 손실을 막는다. 마일스톤 증거와 위험 설명은 저장 사실과 관리자 판단을 구분해 과도한 자동화 주장을 피한다. 현재 제품의 ERP 원본·Calendar 단방향 투영, 역할 보호, 낙관적 동시성, 미확정 저장 복구 관례를 그대로 따른다.

아래 수치는 **제안된 사용성 합격 목표**이며 아직 측정값이 아니다. 대표 사용자 각 역할 5명 이상으로 과업을 측정할 때, 구성원의 “권한 있는 3개 프로젝트에서 오늘 우선 TASK와 다음 시간 찾기” 성공률 90% 이상·중앙값 60초 이하, MANAGER의 “지연 이유와 직접 영향·마일스톤 증거 누락 찾기” 성공률 85% 이상·중앙값 120초 이하, TASK에 일정과 기존 파일 참조 연결 성공률 90% 이상·중대한 권한 오해 0건을 목표로 한다. 390px 및 키보드 전용에서 동일 핵심 과업 완료율 차이는 데스크톱 대비 10%p 이내, 상태 네 축의 구분 질문 정답률은 90% 이상을 목표로 한다.

기능 합격 조건은 다음과 같다: 레거시 미연결 데이터가 재입력 없이 읽기·편집된다; 권한 없는 교차 프로젝트 결과와 집계를 서버가 제외한다; 일반 회의는 기본 TASK 없이 저장되고 TASK는 여러 시간 블록과 연결된다; 기본 TASK 지정·변경·해제·재지정은 모든 진입점에서 MANAGER 또는 그 일정의 `createdBy` MEMBER만 수행한다; 타인 생성 일정을 읽을 수 있는 TASK 담당 MEMBER는 계획 권한으로 보조 관련 링크만 추가·해제하며 기본 TASK와 일정은 편집하지 못한다; 접근 불가·다른 프로젝트 대상과 stale revision은 거부되고 초안이 보존된다; 위험은 근거와 기준 시각을 노출한다; Drive 열기 상태, 마일스톤 결정, 고급 여섯 계획 보기와 일정 속성·저장 보기, 감사 이력이 유지된다.

계획 검증은 텍스트 프로토타입 역할별 인지 검토, 권한 매트릭스 점검, date-only/시간대 경계 사례, 390/1280/200% 재배치, 키보드·스크린 리더, 상태별 계약 테스트로 제안한다. 실행하지 않은 검증은 실제 사용자 과업, 인증된 운영 ERP, Google Drive/Calendar OAuth와 파일 열기, 실제 모바일 기기, 스크린 리더, 색 대비 자동 감사, 브라우저 저장·충돌·권한 회수 시나리오, 제품 단위·통합·E2E 테스트다.

열린 결정은 구현 전 부모 계약에서 확정한다: 개인 `내 작업`의 사용자 시간대 원천과 변경 이력, 마일스톤 증거 삭제 정책, 저장 불명확 상태 조회 API, 부분 성공 집계 표현, 기능 비활성화 시 새 링크의 읽기 노출. 이 결정은 확정된 링크 권한이나 네 상태 축을 바꿀 수 없다. 상위 `SYNTH r1`, UI `r2`, 기준 소스 중 하나가 바뀌면 영향받는 후속 계획·리뷰는 stale이다.
