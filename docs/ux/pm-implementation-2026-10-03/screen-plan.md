## Workflow and screen structure

- Stage 1: `/projects/:id` adds an existing-facts TASK summary linking to `/projects/:id/plan?mode=default`; `/projects/:id/plan` defaults to a limited TASK list and title/state quick-create. `Advanced planning` retains roadmap/hierarchy/tasks/board/milestones/calendar, filters, 50-item pages, history, dependencies, and inline editing. `/projects/:id/schedules` remains the advanced schedule workspace.
- Stage 2 project definition: after `/` creates the project through existing `POST /api/v1/projects`, optional `Add operating definition` saves separately through `PATCH /api/v1/projects/{projectId}/management`; optional target dates save separately through existing `PATCH /api/v1/projects/{projectId}/plan` and its own version. `/projects/:id/settings` edits definition and target dates as two labelled regions. A definition or target failure never deletes the project or rolls back the other success.
- Partial-create recovery: after project creation, show `Project created` immediately. If definition save fails, retain its draft and link to settings with `Retry definition`; if target save fails, retain its date-only draft and `Edit target dates`. On either 409, fetch that resource, show latest versus draft and overlapping fields, then let the user revise and submit against the new version. If one region saved, mark only that region saved; revisiting settings loads saved values and reopens only the unsaved draft.
- Stage 2 TASK and personal work: TASK create/detail loads `GET /api/v1/projects/{projectId}/management/tasks?itemIds=...` and edits priority/completion criterion with `PATCH /api/v1/projects/{projectId}/management/tasks/{itemId}`. `/work?range=today|week|all&projectId=...&assignee=mine|unassigned&page=...&q=...` calls `GET /api/v1/me/work` with the same parameters plus `timeZone`; it shows project, original TASK, execution metadata, blocking reason, and next schedule.
- Browser time context: resolve the browser IANA zone and display/send it as `timeZone`; if resolution fails, display `UTC fallback` and send `UTC`. Responses display returned `timeZone`, `asOfDate`, and `observedAt`. This is per-read context, not a saved preference; it never changes TASK dates or stored schedule instants.
- Stage 2 relationships: TASK detail uses `GET/PATCH /api/v1/projects/{projectId}/management/tasks/{itemId}/references`; schedule detail/edit uses `GET/PATCH /api/v1/projects/{projectId}/management/schedules/{scheduleId}`. `Primary TASK` stays separate from `Related TASK/MILESTONE`. ## State and accessibility coverage

- Keep four independent axes: TASK state, schedule state, current-user acknowledgment, and Calendar projection. Never combine them or mutate one because another changed.
- Composed reads retain heading, filters, reference date, and zone while loading. Each failed region keeps successful regions and its own retry. When `complete=false`, label results `Observed within this query scope`, show only observed/page counts, and suppress total denominators, overall progress percentages, and capacity claims even if a response carries `totalCount`.
- A 403 freezes the affected controls, preserves the draft, removes protected stale data, and offers access recheck. A 409 shows latest resource, submitted draft, and overlaps. The user reloads, edits, and resubmits with the latest `rowVersion`; no automatic overwrite occurs.
- Every new write uses a new UUID `requestId` and `rowVersion`. During an unknown outcome, lock the submitted payload separately from editable display, show `Save result unresolved`, and call `GET /api/v1/projects/{projectId}/management/requests/{requestId}`. `APPLIED` triggers an original-resource refresh. A 404 means unresolved, not failed; `Retry same request` replays only the identical canonical payload and ID. To modify after an unresolved write, first resolve/replay and refresh it, then reopen editing with current values/version and a new request ID. Never send a changed payload with the old ID or blind-retry automatically.
- At 1280px use semantic tables and stable headers; at 390px reflow into labelled blocks without merging relationship types or axes; at 200% preserve DOM/visual order and avoid page-level horizontal scrolling. Keyboard order is shell/navigation, heading/action, filters, summary, records, pagination. Dialogs trap focus, Escape closes, and focus returns. Use visible focus, non-color status names, 44px targets, locale formatting, tabular numerals, wrapping error/permission/zone text, and reduced motion.
