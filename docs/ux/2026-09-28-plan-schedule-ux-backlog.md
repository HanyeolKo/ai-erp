## 1. 계획 목록 가독성과 탐색 맥락

- [ ] 기본 로드맵을 EPIC·TOPIC·마일스톤 중심으로 구성하고 필요한 주제의 TASK만 펼친다.
- [ ] 작업 행의 상태·담당자 중복 표시를 제거하고 날짜 편집 칸은 필요할 때 연다. 상태 변경 등 빈번한 동작에 불필요한 확인 단계를 추가하지 않는다.
- [ ] 공통 검색·담당자·프로젝트 범위와 보기별 유형·정렬·그룹 설정을 구분한다.
- [ ] 보드를 보고 작업 목록으로 돌아와도 그룹·정렬·펼침 상태를 복원한다.
- [ ] 실제 표시되는 유형과 건수를 안내한다. 검토 데이터에서 취소를 제외한 TASK는 66개다.
- [ ] 검색 결과에서 상위 경로를 알 수 있게 하고, 검색 해제 시 사용자의 펼침 상태로 복원한다.

완료 기준: 기본 로드맵에서 상위 항목 7개를 먼저 읽을 수 있고, TASK를 명시적으로 펼칠 수 있다. 작업→보드→작업 이동 후 설정이 유지된다. 390px와 키보드에서도 찾기·펼치기가 가능하다.

## 2. 알림 내용과 후속 행동

- [ ] `SCHEDULE_CHANGED` 이벤트와 화면 문구를 맞춘다.
- [ ] 알림에 프로젝트명·일정 제목·변경자·발생 시각·변경 요약을 제공한다.
- [ ] 새 알림은 발생 당시 정보를 보존하고, 이후 취소 등 현재 상태와 구분한다.
- [ ] 과거 알림에 없는 변경 전후 값은 추정하지 않는다. 현재 조회한 정보와 기록 없음 상태를 명시한다.
- [ ] 제목과 변경 요약을 중심으로 행을 구성하고 읽지 않음·확인 필요·단순 업데이트를 구분한다.
- [ ] 내용을 정상적으로 연 뒤 읽음 처리한다. 읽음과 일정 확인(acknowledgement)은 별개로 유지한다.
- [ ] 권한 회수·삭제·링크 없음·알 수 없는 유형에서 정보 노출과 막힌 이동을 방지한다.
- [ ] Google 동기화 결과는 보조 정보로 두고, 사용자의 조치가 필요한 실패만 강조한다.

완료 기준: 상세 화면을 열기 전 어떤 일정에 무슨 일이 생겼는지 판단할 수 있다. 과거 확정 알림의 현재 일정이 취소 상태이면 두 시점을 설명한다. 알림을 읽는 것만으로 일정 확인 상태가 바뀌지 않는다.

## 3. 반복 등록과 마일스톤 관계

- [ ] 토픽 안에서 TASK를 바로 추가하고 `저장 후 다음 TASK`로 연속 입력한다.
- [ ] 상위 주제·종류·담당자 유지 범위를 명확히 하고, 날짜를 의도치 않게 복사하지 않는다.
- [ ] 마일스톤의 달성 조건 업무와 마일스톤 이후 시작하는 업무를 구분한다. 기존 `successorIds`를 달성 조건으로 해석하지 않는다.
- [ ] 마일스톤에 적절한 날짜·연결 업무·상태를 표시하고, 의미 없는 TASK 진행률 표시는 줄인다.

완료 기준: 같은 토픽에 TASK 3개를 생성할 때 창을 반복해서 열거나 상위 주제를 재선택하지 않는다. 마일스톤의 두 방향 관계를 혼동 없이 확인한다.

## 4. 남은 통합 검증

- [ ] 계획 생성→업무 배정→일정 변경→알림 수신→내용 확인 흐름을 처음부터 끝까지 검증한다. 계획 항목과 시간 일정의 실제 연결 범위도 확인하며 존재하지 않는 자동 연결을 가정하지 않는다.
- [ ] 다중 사용자·권한·동시 수정·미저장 초안·실패 후 재시도를 확인한다.
- [ ] 모바일·키보드·초점 복귀·읽기 순서와 반복 입력 횟수를 확인한다.
- [ ] 후속 구현의 변경 영역 검사 및 독립 검토 후, 별도의 PR·배포 결과를 기록한다.
