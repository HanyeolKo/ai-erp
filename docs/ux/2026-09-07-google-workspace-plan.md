# Google Workspace 연동 화면 계획

## 요청과 전문 에이전트 인계

- 작성일: 2026-09-07. 상태: **전문 계획 완료 / 독립 `ui-plan-review` 대기**, revision 4. 상위 HTTP·업무 계약의 최종 범위를 반영했다.
- 실제 인계: `/root`가 `/root/google_integrations_designer`에 화면 계획 전용 작업을 위임했다. 설계자는 앱·테스트·설정 코드를 수정하지 않는다. 구현과 최종 판단은 각각 경량 구현자와 상위/독립 검토자가 소유한다.
- 사용자: 프로젝트 업무를 수행하면서 자신의 Google 계정에 연결된 파일·일정·메일을 사용하는 로그인 사용자. 요청은 기존 OAuth 권한을 활용한 실제 연동과 사용자명에 보이는 토큰 같은 값의 제거다.
- 추가 확인: 사용자는 **Drive 파일 조회·첨부, Gmail 읽기·작성·발송, 기존 Calendar 일정 연동**을 선택했다. 기능 구현 권한과 실제 계정에서 테스트 메일을 보내거나 파일 권한을 바꾸는 권한을 구분한다.
- 첫 진입은 계속 프로젝트 선택이다. Google 연결은 개인 계정의 보조 기능이며 로비 첫 화면이나 프로젝트 개요를 대체하지 않는다.

계정 연결: 상태 확인 → 필요한 기능과 연결 계정 확인 → 사용자가 `Google 권한 연결` 선택 → Google 동의 → 고정된 `#/account/google` 복귀 → 실제 승인 결과를 다시 읽는다. 일부 권한만 허용한 경우 서비스별 완전 승인 기준으로 가능한 기능을 판정한다. Gmail은 readonly와 send가 모두 있어야 가능하며 readonly만 있으면 `권한 추가 필요`(PERMISSION_REQUIRED)로 표시하고 메일함을 조회하지 않는다. Gmail 재연결은 두 권한을 함께 요청한다. 이미 충분히 승인된 Drive/Calendar는 계속 쓸 수 있다. 부분 연결 때문에 기존 vault나 ERP 로그인을 지우지 않고 새 capability를 임의로 추가하지 않는다. 동의 취소도 같은 고정 화면에서 `권한 연결을 취소했습니다`와 재시도를 제공하고 ERP 로그인·프로젝트 사용을 막지 않는다. 로그인 세션과 Google 서비스 승인은 별도로 표현한다. 기존 프로젝트로 돌아갈 때는 기존 프로젝트 선택 링크를 사용한다. 임의 원래 경로로 OAuth 복귀하지 않으며 토큰·OAuth 인증 코드·메일 본문·검색어를 앱 복귀 URL에 넣지 않는다.

이름 표시: 검증된 Google 프로필의 사람 이름 → 공개 표시가 허용된 이메일 → `내 계정` 순서로 정한다. `sub`, 사용자 UUID, access/refresh/ID token을 이름의 대체값으로 사용하지 않는다. 연결 계정 설명·헤더·구성원·초대·참석자도 같은 공개 프로필 계약을 적용한다. 긴 이름/이메일은 화면 너비에 맞게 줄바꿈한다. 상위 조사에서 기존 배포 기준 `1e2435b`의 Projects는 `계정 {me.data?.id}`로 ERP UUID를 표시했고 현재 `58bc6d6`은 OIDC fullName을 저장한 displayName을 사용한다. 직접 토큰 매핑은 확인되지 않았다. 임의 문자열 패턴으로 정상 이름을 바꾸는 휴리스틱을 추가하지 않고 프로필 필드 출처와 공개 DTO 계약을 검증한다.

Google 연결 화면의 `Google 서비스 연결 해제`는 확인 Dialog에서 `AI ERP에 저장된 Google 서비스 연결 정보를 지웁니다. 이 계정이 연결한 프로젝트의 Calendar 동기화가 중단됩니다. Google 로그인과 Drive 파일·메일·캘린더 원본은 유지됩니다.`라고 설명한다. 확인하면 서버 서비스 토큰을 삭제하고 개인 리소스 캐시·선택·작성 상태를 정리한다. Google 앱 전체 승인을 철회하는 동작을 섞지 않는다. 실패하면 해제가 완료됐다고 표시하지 않고 개인 데이터 표시를 숨긴 뒤 연결 상태를 다시 확인한다.

## Drive 조회와 첨부

- 개인 Drive 목록 한 페이지는 20개를 기준으로 파일명, 종류, 수정 시각(`modifiedTime`)을 표시한다. 제목 없는 파일은 `이름 없는 파일`. 이름 검색을 명시적 검색 버튼으로 실행하고 `검색 지우기`로 복귀한다. 검색 변경은 페이지와 선택을 초기화한다. 표시 순서는 최근 수정순(`modifiedTime desc`)이며 임의 정렬·전체 선택·대량 다운로드는 이번 범위에 넣지 않는다.
- 프로젝트 파일 참조 목록은 개인 Drive 목록과 별도로 파일명·종류·첨부자의 공개 이름·첨부 시각·Google에서 열기를 표시한다. 최근 첨부순으로 페이지당 25개를 제공한다. 이 목록에 개인 Drive 검색 결과나 미선택 파일을 섞지 않는다. 검색어·메일 본문을 브라우저 URL/영구 저장에 넣지 않는 개인정보 경계 때문에 개인 검색 상태는 화면 메모리에만 유지한다.
- 첨부 선택 창은 `프로젝트에 Drive 파일 첨부`와 대상 프로젝트 이름을 표시한다. 파일 한 개를 선택하고 선택 요약의 이름/종류를 확인한 뒤 `첨부`한다. 클릭 한 번으로 바로 저장하지 않는다. 취소는 프로젝트 데이터를 바꾸지 않는다. 같은 파일의 중복 참조는 추가하지 않고 `이미 첨부된 파일입니다`라고 알려 준다.
- 확정 전 문구: `파일 이름과 링크가 이 프로젝트의 구성원에게 표시됩니다. Google Drive의 파일 접근 권한은 변경되지 않습니다.` 첨부는 링크 참조를 저장하며 파일 자체의 복사·다운로드·ACL 변경을 뜻하지 않는다. 멤버가 링크를 열어도 Google 쪽 권한이 없으면 접근할 수 있다는 약속을 하지 않는다.
- 상위 확정 권한: MANAGER/MEMBER가 참조를 추가하고, 첨부자 또는 MANAGER가 참조를 제거하며, VIEWER는 저장된 참조를 읽는다. `첨부 제거`는 확인 창에서 프로젝트 참조만 제거함을 설명하고 Drive 원본은 삭제하지 않는다. 화면과 서버 권한이 모두 필요하다. 개인 파일 목록은 서버의 `drive.metadata.readonly` 사용으로 조회하며 OAuth 토큰을 JavaScript에 전달하지 않는다. 저장하는 링크는 서버가 만든 허용된 Google provider URL만 사용한다.
- 파일 선택 중 권한 상실이나 계정 변경 시 목록·선택을 숨기고 재연결한다. 개인 목록을 프로젝트 목록 캐시에 넣지 않는다. 선택 당시 정보를 그대로 신뢰하지 않고 저장 전에 현재 계정의 파일 접근을 재확인한다. 남의 계정에서 늦게 도착한 응답은 새 세션의 선택을 복원할 수 없다.

## Gmail 읽기와 작성·발송

- 받은편지함(INBOX)과 보낸편지함(SENT)은 각각 한 페이지 20개, 최신순이다. 받은 목록은 보낸 사람, 보낸 목록은 받는 사람을 주체로 표시하고 제목, 짧은 미리보기, 해당 시각을 제공한다. 긴 문자열·기존 수신 메일의 빈 제목은 안전한 대체 표시로 처리한다. 탭 전환은 검색·페이지를 초기화하고 선택 탭을 보조 기술에도 표시한다. 검색은 명시적으로 실행하며 검색 결과 0개와 해당 편지함의 메일 0개를 구분한다. 목록 조회나 상세 열기는 읽음 상태를 바꾸지 않는다. 읽음 처리·삭제·보관·라벨·자동 답장·기타 폴더 제품화는 별도 범위다.
- 읽기 본문은 일반 텍스트 우선이다. HTML만 있으면 안전하게 텍스트로 변환하거나 검증된 정화 처리를 적용한다. 스크립트, 원격 추적 이미지, 자동 외부 요청, 자동 링크 이동은 허용하지 않는다. 링크는 명시적 클릭으로만 연다. 첨부 다운로드 UI는 이번 범위 밖으로 명확히 둔다.
- `메일 작성`은 제목이 있는 넓은 Dialog다. 발신자는 연결 계정으로 고정하고 To/선택적 Cc·Bcc, 제목, 일반 텍스트 본문 순으로 입력한다. 받는 사람은 사용자가 직접 입력하며 프로젝트 구성원/외부 일정 참석자를 자동으로 채우지 않는다. To 최소 1명, 올바른 주소 형식, To/Cc/Bcc 합계 최대 20명, 제목 1~200자, 본문 최대 100,000자를 서버와 동일하게 검증한다. 공백뿐인 제목은 유효하지 않으며 검토 단계 진입 전에 제목 필드에 `제목을 입력해 주세요` 오류를 표시한다.
- 첫 행동 `보내기 확인`은 발신자, To/Cc/Bcc별 전체 대상, 제목과 본문을 검토하는 단계로 이동한다. 최종 `메일 보내기`만 실제 요청을 만든다. `작성으로 돌아가기`로 수정한다. 확인 전 Google 서비스로 실제 발송·draft 저장하지 않는다.
- 발송 중에는 최종 버튼을 비활성화하고 한 번만 요청한다. 앱 UUID requestId와 서버의 영속적인 SENDING/SENT/UNKNOWN/FAILED 발송 기록을 사용해 route 이탈/재진입/새로고침에서도 중복 발송을 방지한다. 브라우저 저장에는 해당 requestId만 보관하고 본문·수신자·자격 증명을 보관하지 않는다. `전송 결과 확인`은 기록을 읽을 뿐 다시 보내지 않는다. SENT에만 `메일을 보냈습니다`를 표시한다. SENDING은 `전송 결과를 확인하는 중…`, UNKNOWN은 `전송 결과를 확인하지 못했습니다. Gmail의 보낸편지함에서 확인해 주세요.`와 결과 조회/안전한 보낸편지함 링크를 제공한다. UNKNOWN의 같은 시도는 바로 재전송할 수 없다. FAILED는 서버가 확실히 전송되지 않았음을 확인한 상태로 `메일이 전송되지 않았습니다`와 `수정 후 다시 확인`을 제공한다. 이때도 새 UUID로 새 검토·명시적 발송 단계를 거친다. 새 작성은 명시적 사용자 행동으로 시작한다. 서버 기록의 계정 소유권과 세션 가드를 검증한다.
- 작성 중 닫기·화면 이동은 `작성 중인 메일을 버릴까요?` 확인을 제공한다. 서버 draft 저장/브라우저 영구저장은 이번 범위에 넣지 않는다. 계정 전환·로그아웃 시 작성/메일 캐시를 지운다. 다른 계정 세션이 이전 발송 완료 알림·본문을 수신하지 않는다. 구현자가 실제 사용자 계정에서 시험 발송하지 않고 mock 응답으로 확인한다.

## Calendar 기존 일정 연동

- Google 연결 화면은 계정 승인 상태, 일정 상세는 해당 일정의 동기화 상태를 보여 준다. 연결 성공을 곧 일정 동기화 성공으로 표시하지 않는다. ERP 변경과 Google 투영의 실패를 분리하고 Google 변경으로 ERP 원본을 덮어쓰지 않는다.
- MANAGER가 프로젝트 Calendar 설정에서 자신의 연결 계정에 존재하는 쓰기 가능한 Calendar를 명시적으로 선택한다. 한 프로젝트당 대상은 하나이며 다른 계정의 토큰/목록을 노출하지 않는다. 선택 목록은 owner/writer 권한의 Calendar 이름만 표시하고 `이 캘린더 연결`로 확정한다. `연결하면 이 프로젝트의 기존 확정 일정과 앞으로 확정하는 일정이 선택한 Google Calendar에 반영됩니다. Google에서 수정한 내용은 ERP에 반영되지 않습니다.`를 확정 전에 보여 준다. 초안 일정은 전송하지 않는다. 쓰기 가능한 대상이 없으면 Google에서 대상 준비/권한 확인 후 다시 조회하도록 안내한다. 최초 연결은 businessRevision > 0인 확정 일정과 확정 이력이 있는 취소 일정을 제한된 배경 작업으로 반영한다. binding API의 `backfillPending`이 true이면 `기존 확정 일정을 반영하는 중…`을 표시한다. 서버에 없는 퍼센트·건수·예상 시간을 만들지 않는다.
- 프로젝트 `Calendar 연결 해제`는 관리자의 명시적 확인으로 앱의 프로젝트 binding을 지우고 새 전송을 멈춘다. 확인 문구는 `기존 Google Calendar 일정은 그대로 남습니다. 연결 해제 후 새 동기화는 시작하지 않습니다. 이미 Google에 보낸 요청은 해제 후에도 완료될 수 있습니다.`이다. Google 계정의 다른 프로젝트 연결이나 서비스 토큰을 삭제하지 않는다. 다른 대상을 고르려면 먼저 해제한 뒤 연결한다. 연결 확인은 새 대상 이름과 함께 `이전에 연결한 캘린더의 일정은 유지됩니다. 다른 캘린더에 연결하면 두 캘린더에 일정이 남을 수 있습니다.`를 밝힌다. 이전 대상 이름의 영구 저장이나 표시는 요구하지 않는다. 동일 대상으로 재연결하면 안정적인 이벤트 ID로 정합성을 맞춘다. 서버의 binding 해제가 확인된 경우에만 연결 해제 성공으로 표시하고 이미 전송한 요청이 철회됐다고 표현하지 않는다.
- 연결 화면·일정 상세에는 실제 대상 Calendar 이름과 binding API의 `ownerName`을 표시한다. 임의 primary Calendar 대체는 없다. 안정적인 이벤트 ID와 서버의 조건부 갱신으로 취소를 반영한다. UI 문구는 `확정 일정 취소도 반영됩니다`이며 제공자가 취소 기록을 영구 보존한다는 약속은 하지 않는다. Google attendees는 생성하지 않고 `sendUpdates=none`으로 초대/변경 이메일을 보내지 않는다. ScheduleForm의 기존 `외부 참석자는 Calendar 일정에만 표시됩니다.` 문구는 `외부 참석자 이메일은 일정 정보로 저장됩니다. Google Calendar 초대 메일은 보내지 않습니다.`로 바로잡는다. 이 파일의 변경도 상위 frontend 구현 계약이 소유한다.
- 기존 확정/변경/취소 및 재시도 흐름을 보존한다. 현재 projection 상태와 revision만 사용하고 마지막 성공 시각을 만들지 않는다. 대기/실패 시 구체적 상태와 가능한 `동기화 다시 시도` 또는 `권한 다시 연결`을 제공한다. Google 재시도 때문에 일정 저장/확정 버튼을 다시 누르게 하지 않는다. 원시 제공자 에러나 토큰을 안내문에 넣지 않는다.

| 404/삭제된 파일·메일 | 해당 항목을 사용할 수 없음을 알리고 목록으로 돌아간다. 프로젝트의 기존 파일 참조는 권한 변경을 추측해 다른 사용자에게 삭제하지 않는다. |

키보드 순서는 제목 → 계정/연결 정보 → 검색/주행동 → 목록 → 페이지 이동이다. 기본 button/link/label 의미를 유지하고 목록의 파일명/메일 제목에 접근 가능한 전체 이름을 준다. Dialog는 제목 연결·초점 가두기·Escape·호출 버튼 복귀를 제공하되 작성 내용이 있으면 버리기 확인을 거친다. 화면 이동은 h1으로 초점을 옮긴다. 일반 텍스트 대비 4.5:1, 큰 글자·주요 UI 3:1, 터치 표적 44px, 가려지지 않는 focus-visible을 확인한다. 320/375/1440px와 200% 확대에서 가로 overflow 없이 긴 이름/주소를 줄바꿈한다. 데스크톱의 목록과 읽기 구분은 모바일에서 목록→상세 단일 열로 바뀐다. 동작을 이해하기 위한 애니메이션이 필요하지 않으며 reduced-motion을 존중한다.

## 결정, 검증 기준과 미실행 항목

| 기준 | 예정 검증 |
| --- | --- |
| GW-01 프로젝트 첫 depth | 일반 로그인은 프로젝트 선택, Google 기능은 계정 메뉴를 거쳐 진입한다. 기존 프로젝트·초대 직접 링크 복귀를 유지한다. 라우트와 실제 브라우저로 확인한다. |

| GW-04 Drive 경계 | 개인 조회와 프로젝트 참조의 공개 범위가 분리되고 명시적 선택·첨부로만 저장된다. 중복·권한 상실·다른 계정의 늦은 응답·기존 Google ACL 불변을 검증한다. |

| GW-07 Calendar | 실제 어댑터 요청/오류 분류/멱등 재시도와 ERP 확정 유지, 명시적 대상 선택, 기존 확정 일정 배경 전송/backfillPending, 초안 제외, 해제 후 기존 Google 이벤트 유지/새 dispatch 중단과 이미 보낸 요청의 한계 안내, 같은·다른 대상 재연결 안내, 취소 반영, 재인증 고정 복귀를 검증한다. 실제 계정 외부 쓰기는 별도 승인 전 하지 않는다. |
| GW-08 접근성·반응형 | 위 viewport, 긴 한국어/이메일, 키보드 Dialog·작성 버리기·focus 복귀, 상태 읽기, 대비를 DOM과 브라우저로 확인한다. |

상위 결정으로 Drive 프로젝트 참조/역할, 개인 Gmail 읽기·작성·발송, 수신자/본문 제한, 발송 receipt, 관리자의 기존 writable Calendar 선택·기존 일정 배경 반영·해제 및 재연결 정책과 외부 알림 없음이 확정됐다. 미결된 화면 정책은 없다. 소스 근거와 pinned 가이드만 검토했고 이번 설계 단계에서 브라우저·접근성·실제 Google 연결/발송·코드 테스트를 실행하지 않았다. 독립 리뷰 문서와 승인 verdict는 상위 handoff 뒤 연결한다.
