## Workflow and screen structure

- Canonical DOM and reading order: header -> `Project progress` -> `Goals` -> `Critical risks` -> `Milestones` -> `My active tasks` -> `Project schedules` -> `Needs my confirmation` -> existing schedule signals and configured cards. The new macro priority supersedes the audit's earlier My-tasks-first fold.
- Header keeps one `h1`, project context, existing invite/create-schedule actions, and current capability rules. Reading Overview sends no mutation: no acknowledgement, notification mark-read, plan write, or schedule write.
- `Project progress` is the only headline metric. When Plan is complete and `taskCount>0`, show `doneCount / taskCount` and API `progressPercent` together, explicitly labelled “unweighted TASK completion.” With zero TASKs, say “No TASK completion percentage.” With partial/unavailable Plan, omit a percentage. Show manual target and forecast as separate labelled facts; render `EMPTY`, `UNDATED`, `INCOMPLETE`, and `COMPLETE` explicitly, label known incomplete bounds, and describe `outsideTarget` only as outside the manual target.
- Each domain exposes one count in its section heading and nowhere else: total goals, critical risks, milestones, active tasks assigned to me, schedules today, schedules this week. Complete data uses `N`; partial data uses `N loaded`; unavailable data shows no number. Existing schedule-only signals remain separate and retain their current meanings.
- `Goals` lists at most 3 non-cancelled EPICs in accepted priority order. Each row shows title and descendant TASK `done/task` plus blocked/overdue facts; TOPIC detail may clarify the goal but never creates weight. `Open Plan hierarchy` links to `/projects/{id}/plan?view=hierarchy&types=EPIC,TOPIC`.
- `Critical risks` lists at most 5 active TASKs in the accepted blocked, overdue, unplanned, unassigned order. Each row names every applicable reason, title, parent path, state, and nearest applicable date; it never assigns severity or project health. `Open all tasks` links to `/projects/{id}/plan?view=tasks&types=TASK`.
- `Milestones` lists at most 5 non-cancelled MILESTONEs with title, state, and first applicable deadline/target date; undated items say so. `Open milestones` links to `/projects/{id}/plan?view=milestones&types=MILESTONE`.
- `My active tasks` lists at most 5 accepted self-assigned, non-DONE/non-CANCELLED TASKs with title, parent path, state, due date, and blocker reason. `Open all assigned tasks` links to `/projects/{id}/plan?view=tasks&types=TASK&assigneeId={me}` and does not claim the destination excludes DONE.
- `Project schedules` has `Today` and `This week` pressed-state buttons backed only by Overview URL `period` and valid IANA `zone`. “Today” always means the actual wall-clock civil date in that zone; “This week” is the Monday-to-next-Monday window containing that date. Do not restore a historical date as Today or add date browsing. Compute both counts from the same current-week rows, so switching to Today is immediate; at zone midnight, recompute the civil date and boundaries, start a new schedule request epoch, and refresh the affected counts/list. State the current civil range and zone, and list only the selected period; each row links to existing schedule detail. `Open calendar` uses `/projects/{id}/schedules?view=builtin-calendar&mode=week&date={currentZoneCivilDate}&zone={zone}`. A period switch updates one history entry; refresh and Back restore period and zone, then derive the current date anew.
- `Needs my confirmation` preserves the existing queue and opens schedule detail for the explicit action. Hide the queue for VIEWER. Existing configured cards and the selected main's current explicit notification behavior remain intact and secondary; this increment neither imports PR24 notification changes nor owns future notification evolution.

## State, permission, and recovery coverage

- Each Plan-derived section can be initial loading, complete, empty, partial, unavailable, or refreshing. Preserve visible safe data during a non-access refresh and label it stale; `complete=false` rows and counts always say loaded. A successful complete zero snapshot uses directional empty copy and Plan links.
- The schedule region can be loading, complete, empty, partial, unavailable, or refreshing. First-page non-access failure is unavailable; later non-access failure retains deduplicated rows as partial; zero-new-id or 50-page ceiling is partial. Access-denial at any page enters the shared project-wide access failure instead.
- `PROJECT_ACCESS_DENIED` or qualifying 403/404 hides and discards every protected project region, confirmation queue, dashboard signal, and configured card; cancels/removes project queries and locks actions. Global 401 remains session termination. One project-level recovery action starts a new access revision; no region reappears until fresh membership and its own fresh read succeed in the same session/project/revision/date-zone epoch.
- Late responses are accepted only for the active session generation, project id, access revision, and schedule zone/from/to. Project, session, denial, recovery, zone change, or zone-midnight boundary change invalidates obsolete work. Independent non-access resource errors keep other authorized regions usable.
- MANAGER/MEMBER retain current create/edit/confirm/acknowledge capabilities at their existing destinations. VIEWER receives read-only values and navigation links, with no create/edit/confirmation queue or disabled pseudo-actions. Overview never broadens a role.

- Use native headings, regions labelled by their `h2`, lists, links, buttons, `time`, and text/definition pairs. If a progress graphic is used, its accessible name/value must repeat the visible ratio; when the percentage is unknown, expose plain status text and no indeterminate health interpretation.
- Keyboard order follows the canonical DOM order. Existing skip link and route-heading focus remain; period buttons expose `aria-pressed`; retries name their region; loading/refresh uses polite status, failures use alert, and one concise polite message announces period/result changes. Focus returns to the invoking link after cancel/Back and is never moved merely by background refresh.
- At 1440px all seven primary regions remain scan-first and the first record/state of the macro group is reachable without decorative content. At 768px and below use the same single-column DOM order. At 390px, 320px, and 200% zoom use read-first list records rather than tables, retain 16px page gutters and 44px targets, wrap long Korean titles/paths/IDs, keep focus unclipped, and limit page horizontal overflow to 1px; no content is hidden behind hover or truncation.
