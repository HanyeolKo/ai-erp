## Workflow and screen structure

- Notification primary flow: from any project Shell, activate a semantic `알림` button; keep the current hash, scroll position, filters, and page mounted; open a modal titled `알림`; load page 1 through the existing notification query; retain server order, type/time labels, safe related-project/schedule links, read state/action, and previous/next pagination. A successful related link closes the modal and follows the existing validated internal hash destination. Closing without navigation restores focus to the invoking button and leaves page context unchanged.
- Notification alternate flow and compatibility: direct/bookmarked `#/notifications` remains supported as the existing full-page notification view with identical content semantics. Refresh/back on that URL remains valid. The header entry does not push `#/notifications`; browser Back therefore continues to mean the user’s preceding navigation. Share one notification content behavior between modal and route so read invalidation, disabled pending state, errors, allowlist, and pagination cannot diverge.
- Notification state boundaries: initial open shows a named dialog immediately; loading is announced without stale-page confusion; empty copy remains; query error remains visible with the existing query recovery; read pending disables duplicate read actions without blocking close or unrelated safe links; read success refreshes current notification data; read error stays associated with the dialog. Session expiry retains the global boundary. No unread count, polling, mark-all-read, optimistic read, or new permission is introduced.
- Calendar primary flow: one period toolbar presents, in reading/tab order, month/week segmented controls; previous-period button; a single current-period/date-jump control showing the visible month or week range; next-period button; and `오늘` (Today). Previous/next uses existing `navigateDate(anchor, view, ±1)` and resets result page. Today sets the anchor to today in the active valid display timezone and resets result page. Switching view retains the anchor date and resets result page.
- Date jump: activating the current-period control opens a small date-selection dialog/popover labeled `날짜로 이동`, with one labeled native date input initialized from `anchor`, explicit `이동` and `취소` actions, and no data mutation. `이동` accepts only `YYYY-MM-DD`, applies the anchor, resets result page, closes, and returns focus to the period control; invalid or empty input keeps the overlay open with an associated error. Escape/cancel makes no change. This removes the permanently exposed label/input height mismatch while retaining a native, keyboard-accessible date selector.
- Calendar boundaries: the displayed period summary, API `from/to`, grid/agenda days, and date jump all derive from the same anchor/view/valid timezone. Detailed `날짜 이후/이전` filters remain independent and inclusive; navigation must not clear or rewrite text/status/ack/mine/date filters. Invalid timezone continues to fall back to `Asia/Seoul` with its existing alert. Preserve valid date handling, month 42-cell Monday grid, seven-day week, mobile agenda, schedule ordering, pagination, safe detail links, capabilities, and all drag/resize/time-edit locking, preview, PATCH, conflict, and recovery behavior.
- Responsive behavior and existing product conventions: preserve ERP-WORKSPACE-01/v2 shell and tokens. Desktop/tablet keep one aligned toolbar row where space permits; every control shares the same visual control height and baseline. At `<768px`, retain agenda replacement and wrap the toolbar into logical rows without reordering: view toggle, then period navigation, with 44px targets and no page-level horizontal overflow at 390/375/320px or 200% zoom. Visual specialist may choose icon treatment only with persistent accessible names; it may not change these actions or state transitions.
