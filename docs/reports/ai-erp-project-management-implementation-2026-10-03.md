## 현재 결과

개정된 AI ERP 하네스는 PR #25와 기준 커밋 `b660`에 반영되었다. 현재 PR #26은 그 기반에서 프로젝트 관리 기능을 구현하는 초안이다. 백엔드 기반 작업 B1과 프런트엔드 1단계 F1은 각각 Luna/high 구현자가 최초 구현과 두 차례 수정을 수행해 총 세 번의 시도를 사용했다. 두 작업 모두 독립 Astra/high 소스 검수에서 `FAIL`을 받았으므로, 구현 완료나 병합 가능 상태로 보지 않는다.

백엔드는 세 번째 검수 대상이었던 기존 결함 9개 가운데 5개를 닫았고 4개가 남았으며, 빈 페이지 집계 결함 1개가 새로 확인되었다. 현재 남은 핵심 문제는 저장 의미와 요청 해시의 유니코드 공백 정규화 불일치, OpenAPI의 선택 매개변수·기본값·숫자 제약 오류, PostgreSQL 회귀 시나리오 부족, 관계 그래프의 정확한 10,000개 경계와 프로젝트별 조회 범위, 범위 밖 빈 페이지의 전체 개수 보존이다. 최초 진단 커밋 `8fd669`의 CI 실행 `37115098605`와 현재 게시 후보 `f479ee8da78a322ec5d6c7bc093cc75f7673347d`의 CI 실행 `37116551321`은 모두 하네스 검사를 통과했지만 배포 계약 검사에서 실패했으며, PostgreSQL 검사는 실행되지 않았다. 새 V11 마이그레이션의 파일명·개수·체크섬을 배포 허용 목록에 정확히 반영하고 누락·변조 방지 검사를 추가해야 한다. 실제 PostgreSQL 성공 근거는 아직 없다. 자세한 판정과 제한된 수정안은 [B1 검수](../planning/pm-implementation-2026-10-03/backend-b1-repair3-review.md), [부모 자체 검토](../planning/pm-implementation-2026-10-03/backend-b1-parent-self-review.md), [추가 시도 계약](../planning/pm-implementation-2026-10-03/backend-b1-exception-repair-contract.md)에 있다.

프런트엔드는 기존 결함 9개 가운데 4개를 닫았고 5개가 남았으며, 필수 회귀 검사 누락과 부분 관측 표시 결함 2개가 추가되었다. 기존 전체 테스트 341개와 표적 테스트 109개, 타입 검사, 빌드는 통과했지만 새로 요구된 9개 조건을 모두 검증하는 검사는 아니다. 실제 브라우저에서는 새 버튼이 44px이고 필터 라벨이 보이며 VIEWER의 읽기 전용 안내가 개선되었다. 1280px 화면의 첫 행은 68.5px로 목표 밀도를 벗어났고, 기존 TASK가 있으나 일정이 없을 때 첫 TASK 안내가 잘못 표시된다. 500 오류가 발생해도 정상 영역을 유지하는 동작은 일부 개선되었지만, 현재 TASK 요청이 403을 반환할 때의 보호 처리, 입력 초안이 5분 뒤 삭제되는 문제, 저장 응답이 오기 전에 화면을 떠났다 돌아올 때 초안과 요청 ID를 지키는 동작, 화면에 보이지 않는 선행 작업의 차단 정보, 일부 결과만 받은 화면의 안내가 남아 있다. 알 수 없는 500 응답 뒤 동일 요청 ID와 payload를 유지하고 짧게 다른 화면에 다녀오는 동작은 확인했으나, 이 결과만으로 5분 이후의 초안 보존과 저장 중 화면 이동 문제가 해결되었다고 볼 수 없다. 자세한 내용은 [F1 검수](../planning/pm-implementation-2026-10-03/frontend-s1-repair3-review.md), [부모 자체 검토](../planning/pm-implementation-2026-10-03/frontend-s1-parent-self-review.md), [추가 시도 계약](../planning/pm-implementation-2026-10-03/frontend-s1-exception-repair-contract.md)에 있다.

## 현재 사용할 수 있는 범위와 남은 범위

현재 초안에는 백엔드 운영 정의·TASK 실행 정보·개인 작업 API와, 프런트엔드의 TASK 중심 진입점·기본 작업 화면·개요 요약·역할별 읽기 전용 표현이 들어 있다. 기존 고급 계획 경로를 보존하고, 요청 결과가 불명확할 때 같은 요청 ID로 결과를 다시 확인하는 기반도 포함한다. 다만 이 구현은 검수에서 실패한 후보이므로 완성된 기능으로 볼 수 없다. 이번 검증은 오프라인 시험 데이터와 브라우저 관찰을 사용했으며 자격 증명이나 실제 외부 제공자 호출을 사용하지 않았다. 따라서 기존 ERP 또는 Google 연동 준비 상태를 새로 증명하지 않았고, 이번 결과를 실제 연동 성공 근거로 사용할 수 없다.

아직 구현되지 않은 S2 범위는 운영 정의를 설정하는 사용자 화면, TASK 실행 정보를 편집하고 확인하는 화면, 내 작업 화면, 일정 문맥과 파일 연결 기능 전체이다. S3의 마일스톤 검토와 주간 위험 기능도 구현되지 않았다. 남은 작업은 기능 범위를 줄이거나 실패 횟수를 초기화하지 않고, 시작하지 않은 작업만 더 작은 패키지로 나누는 방안이 제안되어 있다. 구체적인 선후 관계는 [후속 작업 배정안](../planning/pm-implementation-2026-10-03/remaining-task-dispatch-proposal.md)에 있으며, B1과 F1이 실제로 수락되기 전에는 후속 패키지를 시작할 수 없다.

## 다음 결정

B1과 F1에는 각각 같은 Luna/high 구현자가 수행할 추가 시도 1회만 예외적으로 허용하는 계약이 준비되어 있다. 이는 네 번째 시도를 이미 승인했다는 뜻이 아니다. 현재 사람의 승인이 필요한 두 질문이 대기 중이며, 승인 전에는 작업자를 다시 배정하거나 모델을 올리거나 시도 횟수를 초기화하지 않는다. 승인할 경우에도 두 작업은 계약에 적힌 결함만 수정하고, 실제 동일 커밋 PostgreSQL CI와 독립 Astra/high 검수, 부모 수락을 모두 통과해야 한다. 필수 검사가 통과하기 전에는 PR #26을 병합할 수 없다.
