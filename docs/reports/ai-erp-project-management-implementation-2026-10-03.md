## 백엔드 B1

B1의 네 가지 기존 소스 수정은 재사용되었고, 빈 검색어 `q` 때문에 PostgreSQL이 `lower(bytea)` 오류를 내던 제품 코드도 수정되었다. JDK 25 환경에서 로컬 대상 검사, 통합 검사 컴파일, 최종 테스트, OpenAPI 생성, `bootJar`가 성공했다. 실제 PostgreSQL CI에서 실패한 유일한 검사는 권한을 회수한 프로젝트를 제외한 작업 페이지의 개수를 확인하는 검사였다. 이 검사는 155행에서 `1L`을 기대했지만 실제 값은 `2L`이었다. 검색어 `Task`가 제목과 두 번째 항목의 설명에 모두 일치하므로, 이 실패는 기존에 확인된 검색 기대값 오류와 일치한다.

이전 후보에서 나타난 빈 검색 매개변수의 `lower(bytea)` 오류, 마이그레이션의 `BIGINT` 기대값 오류, 비활성 서비스 검사의 트랜잭션 오류는 이번 CI에서 재발하지 않았다. 그러나 기존 검사가 통과했다는 사실만으로 정확한 UTC instant 비교, 의도한 receipt `CHECK` 실패의 귀속, OpenAPI 요청 예제와 잘못된 값·누락 조건의 거절 검사가 충분해졌다고 볼 수는 없다.

독립 검수는 두 가지 안정적인 결함군을 유지했다. 첫째, PostgreSQL 회귀 검사는 `Task`가 제목과 두 번째 항목의 설명에 모두 일치하여 실제 전체 개수가 2인데도 1을 기대한다. 마이그레이션 시각을 정확한 UTC instant로 비교하지 않았으며, 의도한 receipt `CHECK` 제약 실패의 SQLSTATE와 제약 이름도 확인하지 않는다. 둘째, OpenAPI 요청 예제 검사는 응답 예제를 읽고 있다. 잘못된 값이나 누락된 조건을 거절하는 지정 검사도 빠져 있다. 따라서 B1은 계속 `FAIL`이다.

## 프런트엔드 F1

실제 로컬 전체 검사는 30개 파일의 355개 검사가 모두 통과했고, 타입 검사와 빌드도 종료 코드 0으로 끝났다. 프로젝트 관리 검사는 21개, 세션 검사는 9개이며, 세션 검사는 이번 수정에서 추가되지 않았다. 실제 Chrome에서는 전체 ASCII 입력이 보존되었다. 이 성공은 아래의 미검증 시나리오와 실행 중 결함을 해소하지 않는다.

F1의 P1 연속성 결함은 그대로 열려 있다. 기존 TASK 상태 변경이 `PATCH 200`으로 끝난 뒤 빠른 작업 생성이 `POST 200`으로 성공했지만, 서로 다른 작업의 요청 기록이 함께 남은 캐시에서 상태 변경 기록에는 `body`가 없었다. 요청 종류와 데이터 구조를 확인하지 않은 조정 로직이 `body.requestId`를 읽으면서 `TypeError`가 발생했고, 제품 화면은 빈 화면이 되었다. 합성 생성 자체는 성공했지만 사용자가 결과를 볼 수 없었다.

P2 회귀 검사도 부족하다. 실제 TASK 요청을 세션 종료 뒤 늦게 완료하는 경우, 화면을 떠난 뒤 비활성 초안 타이머가 만료되는 경우, 성공 데이터를 캐시에 둔 뒤 현재 조회가 403이 되어 보호 캐시를 지우면서 본인 초안을 보존하는 경우, 그리고 이미 이름이 지정된 나머지 영향 범위를 검사해야 한다.

제한된 복구 시나리오는 성공했다. 결과를 알 수 없는 R5 요청은 실제 해시 경로를 12분 33.375초 동안 떠났다가 돌아온 뒤에도 전체 제목과 `BACKLOG` 상태를 유지했다. 결과 확인은 같은 UUID와 같은 payload를 다시 보냈고, 서버는 원래 TASK를 반환했다. 이 결과는 해당 복구 흐름만 입증하며, 서로 다른 작업의 요청 기록이 함께 남은 캐시에서 발생하는 P1이나 누락된 세션·GC·캐시 회귀 검사를 입증하지 않는다.

## 사용할 수 있는 범위와 남은 범위

현재 초안에는 프로젝트 관리의 백엔드 운영 정의, TASK 실행 정보, 개인 작업 API와 프런트엔드 TASK 진입점, 기본 작업 화면, 개요 요약, 역할별 읽기 전용 표현이 포함되어 있다. 그러나 B1과 F1이 모두 수락되지 않았으므로 완성본이나 배포 가능한 결과로 취급할 수 없다. 실제 ERP·Google 연동과 배포 성공도 확인되지 않았다.

S2의 운영 정의 설정 화면, TASK 실행 정보 편집·확인 화면, 내 작업 화면, 일정 문맥과 파일 연결 기능은 구현되지 않았고 배정되지 않았다. S3의 마일스톤 검토와 주간 위험 기능도 구현되지 않았고 배정되지 않았다.

사용자가 이전에 최종 병합을 승인한 사실은 유지된다. 그러나 필수 검수가 실패했으므로 PR #26은 초안 상태를 유지해야 하며, 병합이나 배포를 실행할 수 없다.
