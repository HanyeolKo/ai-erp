## 현재 결과

PR #26은 프로젝트 관리 기능을 구현하는 초안이다. 백엔드 B1과 프런트엔드 F1의 4차 수정 후보, 그리고 두 작업의 `FAIL` 검수 기록은 위 커밋에 보존되어 있다. 앞선 세 차례의 `FAIL`과 이번 4차 검수의 `FAIL`은 모두 유효하다. 따라서 현재 후보는 구현 완료, 병합 또는 배포가 가능한 상태가 아니다.

백엔드 B1은 검수 항목 6개 중 요청 해시 정규화, 관계 그래프 경계, 범위 밖 빈 페이지의 전체 개수 보존, V11 배포 마이그레이션 검사 등 4개를 소스 수준에서 닫았다. OpenAPI와 PostgreSQL 검증 2개는 열려 있으며, 독립 검수 결과는 계속 `FAIL`이다. 자세한 소스 판정은 [B1 4차 검수](../planning/pm-implementation-2026-10-03/backend-b1-exception4-review.md)에 있다.

같은 커밋의 [GitHub Actions 실행 37131323242](https://github.com/HanyeolKo/ai-erp/actions/runs/37131323242)은 완료되었지만 최종 결과가 `FAIL`이다. 하네스 검사 117개와 스모크 검사, 배포 계약 검사는 통과했다. 실제 PostgreSQL 통합 검사는 61개 중 4개가 실패하여 백엔드 단계 14가 실패했고, 그 뒤의 프런트엔드·API·Docker 단계는 건너뛰었다.

PostgreSQL 실패 4개에는 원인이 3개 있다. 첫째, 실제 개인 작업 조회 코드가 빈 검색어를 `null`로 정규화한 뒤 네 JPQL 조회·집계식의 `lower(concat('%', :query, '%'))`에 전달한다. PostgreSQL은 이를 `bytea`로 해석하여 `function lower(bytea) does not exist` 오류를 냈고, 이 제품 코드 결함이 개인 작업과 권한 회수 뒤 페이지 집계 검사 2개를 함께 실패시켰다. 둘째, V10에서 V11로 올리는 검사는 마이그레이션을 실제로 완료했지만 JDBC `BIGINT` 값 `8L`을 `Integer` 값 `8`과 비교하여 실패했다. 같은 픽스처의 프로젝트 계획과 업무 개정 번호도 `Long`으로 비교해야 한다. 셋째, 비활성화 서비스 검사는 새 서비스를 직접 생성한 뒤 트랜잭션 밖에서 호출하여, 비활성화 확인 전에 필수 프로젝트 잠금이 `IllegalTransactionStateException`을 냈다. 이 두 건은 제품 마이그레이션 SQL 실패가 아니라 검사 코드의 결함이다.

프런트엔드 F1은 검수 항목 7개 중 화면 밀도와 부분 관측 표시 2개를 소스 수준에서 닫았고, 나머지 5개와 새 입력 손실 P1은 열려 있다. 기본 컨트롤은 44px이며, 1280px 화면의 행 높이는 56.5~57px이다. 그러나 실제 브라우저에서 `R4 durable draft a12345`를 입력했을 때 후보 화면에는 `d 5`만 남았고, 이전 후보에서는 전체 문자열이 보존되었다. 작업자가 회상한 전체 성공 결과는 원시 자료로 보존되지 않았으며, 현재 권위 있는 전체 테스트 원시는 346개 중 344개 통과·2개 실패·종료 코드 1이다. 현재 권한 403 처리, TASK가 없지만 일정은 있는 화면, 보이지 않는 선행 작업의 불확실성 표시, 요청 재시도 연속성과 필수 회귀 검사도 아직 부족하다. 자세한 판정은 [F1 4차 검수](../planning/pm-implementation-2026-10-03/frontend-s1-exception4-review.md)에 있다.

다만 결과를 알 수 없는 요청을 보낸 뒤 해시 경로를 떠났다가 돌아오는 제한된 시나리오는 실제 브라우저에서 확인되었다. 14:42:43Z에 떠난 뒤 15:15:24Z에 돌아와 32분 넘게 초안과 확인 동작이 유지되었고, 결과 확인 버튼은 요청 ID `e7c6c9a8-9380-4e4e-9822-0bc41beac90c`와 동일한 payload를 다시 사용했다. 서버는 같은 TASK `task-created-1`을 반환했고 화면은 한 번 초기화되었다. 이 결과는 해당 시나리오만 확인하며, 새 입력 손실 P1이나 전체 브라우저 검사를 해소하지 않는다.

## 현재 사용할 수 있는 범위와 남은 범위

현재 초안에는 백엔드 운영 정의·TASK 실행 정보·개인 작업 API와 프런트엔드의 TASK 중심 진입점·기본 작업 화면·개요 요약·역할별 읽기 전용 표현이 포함되어 있다. 기존 고급 계획 경로와 요청 결과가 불명확할 때 같은 요청 ID로 결과를 다시 확인하는 기반도 유지된다. 그러나 위 결함 때문에 이 기능을 사용할 수 있는 완성본으로 취급할 수 없다.

검증에는 실제 PostgreSQL CI와 제한된 브라우저 관찰이 포함되었다. 전체 브라우저 게이트와 실제 ERP·Google 연동은 확인되지 않았다. 이번 결과는 전체 브라우저 동작, 외부 연동 또는 배포 성공의 근거가 아니다.

S2의 운영 정의 설정 화면, TASK 실행 정보 편집·확인 화면, 내 작업 화면, 일정 문맥과 파일 연결 기능은 구현되지 않았다. S3의 마일스톤 검토와 주간 위험 기능도 구현되지 않았다. B1과 F1을 수락하기 전에는 후속 패키지를 시작할 수 없다.
