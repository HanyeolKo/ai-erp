# 프로젝트 일정 관리 재설계

기준일: 2026-09-22. 이 문서는 로컬 원본이며 구현·검증 결과가 확정되면 같은 문서를 갱신한다.

## 합의된 방향

프로젝트가 하나의 일정 데이터 집합을 갖고, 캘린더·카드·목록은 그 데이터를 다르게 보여 주는 보기다. 대시보드에서도 같은 일정의 상세 내용을 열고 수정할 수 있어야 한다. 사용자는 프로젝트 속성을 만들고, 선택형 속성의 옵션과 색상을 정해 분류·그룹·범례를 구성한다.

텍스트, 숫자, 체크박스, 날짜, 단일 선택 속성을 지원한다. 속성 이름이나 옵션 이름을 바꿔도 기존 일정의 값과 저장된 보기 참조는 유지한다. 사용하지 않는 속성과 옵션은 보관하고 다시 복원한다.

보기에는 필터, 정렬 순서, 그룹, 범례, 표시할 속성을 저장한다. 개인 보기는 본인만 보고 관리하며, 공유 보기는 프로젝트 구성원이 사용하고 관리자가 변경한다. 아무 설정도 없는 프로젝트에도 기본 캘린더·카드·목록을 제공한다.

## 세 안의 비교와 선택

| 안 | 강점 | 주요 비용 | 채택한 부분 |
|---|---|---|---|
| A: 데이터 구조를 엄격히 분리 | 속성 타입과 참조 관계가 명확하고 전체 데이터 조회에 유리 | 보기 설정까지 세분화하면 초기 구현이 커짐 | 속성·옵션·값의 명시적인 저장 구조와 타입 검증 |
| B: 저장된 보기 중심 | 사용자가 같은 일정을 여러 관점으로 관리하기 쉬움 | 데이터 검증과 권한 처리를 별도로 충분히 보강해야 함 | 개인·공유 보기, 간결한 보기 설정 저장 방식 |
| C: 기존 동작과 점진적 호환 | 기존 일정과 외부 연동에 미치는 영향을 줄임 | 값 저장을 지나치게 유연하게 하면 타입·조회 정합성이 약해짐 | 기존 일정 유지, 추가형 마이그레이션, 기본 보기의 무설정 제공 |

교차검증 후 A의 데이터 구조, B의 보기 경험, C의 호환 전략을 결합했다. 독립 검토의 제품 기획 및 기능·시각 계획 심사를 통과했다. 사용자가 구현·PR·병합·배포까지 승인한 범위이며, 현재 검증과 재시도 상태는 아래에 기록한다.

## 구현에서 지켜야 할 기준

- 어느 보기에서 수정하든 같은 일정 ID를 변경한다. 별도의 카드용 일정을 만들지 않는다.
- 필터·집계·정렬은 사용자가 접근할 수 있는 전체 일정에 적용한 뒤 페이지를 나눈다. 현재 페이지의 일부만 필터링하고 전체 결과라고 표시하지 않는다.
- 범례 기준과 그룹 기준은 따로 선택할 수 있다. 색상과 함께 옵션 이름을 표시한다.
- 기존 일정의 확정·취소·참여자 확인·Google Calendar 연동을 유지한다. 사용자 속성만 바꾸는 것은 업무 일정 변경과 구분한다.
- 체크박스의 미설정과 거짓, 숫자 0과 빈 값을 구분한다. 잘못된 타입이나 다른 프로젝트의 옵션은 저장하지 않는다.
- 충돌이나 저장 실패가 발생하면 사용자가 입력한 내용을 보존하고 복구 방법을 제공한다.
- 대시보드는 선택한 공유 보기의 일정 카드를 표시하며 기존 요약과 처리 대기 영역을 유지한다.

## 현재 검증 상태

세 기획안의 교차검증, 통합안, 기능·시각 계획 검토가 완료되었으며 [초안 PR #18](https://github.com/HanyeolKo/ai-erp/pull/18)에 구현과 검증 기록을 보존했다.

백엔드는 소스 `78821a726487b3f5bec38d2322acd73eaf620f12`의 실제 CI `35634074607`에서 단위·REST Docs 146개, OpenAPI 계약 8개, PostgreSQL 통합 47개, 총 201개 검사를 모두 통과했다. 실행 파일 빌드와 API 클라이언트 생성도 성공했고 독립 백엔드 검토는 PASS다. 프로젝트 조건을 명시해 기존 인덱스를 활용하도록 보완했으며, 통계가 갱신된 대표 데이터의 실제 실행 계획은 페이지 조회 424블록, 그룹 집계 106블록으로 기존 5,000블록 기준을 통과했다. 통계 갱신 전후 원본 측정도 보존했다.

프런트엔드는 로컬 267개 테스트·타입 검사·빌드 통과 이력이 있지만, 최신 CI에서는 266개 통과·1개 실패다. 실패 항목은 잘못된 프로젝트 생성 응답 후 복구 상태를 유지하는 검사이며, 소스를 변경하지 않은 단독 재실행에서는 통과했다. 실행 순서나 부하 영향 여부는 아직 확정하지 않았고 전체 CI 통과로 간주하지 않는다. 이후 프런트엔드 타입·빌드와 Docker 빌드 단계는 실행되지 않았다.

별도로 독립 프런트엔드 검토에서 옵션 초안 보존, 권한 거부 후 편집 제한, 공유 보기의 개인 사본 저장, 대시보드 충돌 복구, 페이지 초기화, 소수 필터 및 관련 회귀 검증 등 8개 항목이 남았다. 공유 보기 저장·대시보드 편집·모바일 표시의 일부 흐름은 합성 미리보기에서 확인했으나 전체 수용을 의미하지 않는다.

프로젝트의 3회 구현 시도 한도에 도달해 추가 프런트엔드 구현을 보류했다. 사용자에게 이번 작업에 한한 한도 예외를 요청했으며 답변 대기 중이다. 네 번째 구현 시도, PR 병합, 새 버전 배포는 실행하지 않았다. 기존 병합·배포 승인은 유효하며, 예외가 확인되면 남은 수정·독립 검토·전체 CI·출시 검토를 거쳐 완료할 수 있다.
