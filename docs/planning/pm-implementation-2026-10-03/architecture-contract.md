## S2 exact API contract

All paths below have prefix /api/v1; auth uses the existing ApplicationPrincipal. Text input is trimmed, length-limited, null/blank optional values clear to null; UUID targets must be current readable same-project kind. GETs never grant provider access. Mutations increment resource version and audit actor/time/operation/version; all writes reject missing/stale version and missing requestId.

- GET /project-management/config -> {enabled:boolean} for authenticated users.
- GET /projects/{projectId}/management -> Definition {projectId,purpose:null|string,successCriteria:null|string,responsibleManagerId:null|UUID,health:null|ON_TRACK|WATCH|AT_RISK,healthReason:null|string,healthAsOf:null|LocalDate,rowVersion:long,canEdit:boolean}. Existing plan targetStart/targetEnd remain in original plan API, not duplicated in definition storage.
- PATCH same -> {purpose,successCriteria,responsibleManagerId,health,healthReason,healthAsOf,rowVersion,requestId}. Limits purpose/successCriteria2000, healthReason500; non-null health requires reason/date; responsibleManagerId must be current project MANAGER. Absent definition is readable all-null version0. Existing project create response remains unchanged; optional definition is saved afterward, with explicit partial-create recovery and no automatic project deletion.
- GET /projects/{projectId}/management/tasks?itemIds=UUID,UUID -> {projectId,items:TaskExecution[],complete:true}; at most100 unique TASK IDs, same-project validation. TaskExecution {itemId,priority:null|HIGH|MEDIUM|LOW,completionCriterion:null|string,rowVersion:long,canEdit:boolean}. Missing metadata is null/version0.
- PATCH /projects/{projectId}/management/tasks/{itemId} -> {priority,completionCriterion,rowVersion,requestId}; criterion max2000. Only existing TASK, plan writer; legacy plan updates cannot clear these values.
- GET /me/work?range=today|week|all&timeZone=IANA&projectId=UUID(optional)&assignee=mine|unassigned&page=0&limit=50&q=... -> {items:WorkItem[],page,limit,hasNext,totalCount,complete,asOfDate,timeZone,observedAt}. Default mine/today/50, limit<=100, q<=200. TODAY includes overdue/due today and items targeting today; WEEK uses Monday-Sunday in requested zone plus overdue; ALL all non-DONE/non-CANCELLED TASKs. WorkItem {projectId,projectName,projectRole,item:original ItemResponse,execution:TaskExecution,nextSchedule:null|{scheduleId,title,startsAt,endsAt,status},blockingReason:null|string}. Server current-readable-project filter before paging/counting; inaccessible project filter denied. Stable ordering attention(blocked/overdue), priority HIGH/MEDIUM/LOW/null, deadline null-last, title, UUID. No booked-hours/capacity inference. Use project-owned immutable membership/project-name lookup, not private membership repositories in projectplan. Bound large scope explicitly; never silently report incomplete results as complete.
- GET /projects/{projectId}/management/schedules/{scheduleId} -> ScheduleContext {projectId,scheduleId,primaryTaskId:null|UUID,relatedItemIds:UUID[],rowVersion,canEditPrimary,canEditRelated}. Version0 empty for legacy unlinked schedule. Validate schedule in project via immutable lookup.
- PATCH same -> {primaryTaskId,relatedItemIds,rowVersion,requestId}. Only changed fields' source authority is required: primary set/change/unlink/reassign uses schedule writer; related-only edits use plan writer. Related target kinds TASK/MILESTONE, max50; primary TASK only. Do not accept unauthorized unchanged-plus-changed fields to bypass authority. No invitations, date copy, status change or provider call. Audit old/new links and preserve missing targets explicitly.
- GET /projects/{projectId}/management/tasks/{itemId}/references -> TaskReferences {projectId,itemId,fileReferenceIds:UUID[],milestoneIds:UUID[],rowVersion,canEdit,files:[{referenceId,exists:boolean,openState:UNKNOWN}],schedules:[{scheduleId,relation:PRIMARY|RELATED,exists:boolean}],milestones:[{itemId,exists:boolean}]}. Enrich names/times only from currently readable source APIs; do not expose removed target metadata.
- PATCH same -> {fileReferenceIds,milestoneIds,rowVersion,requestId}; plan writer, max50 each, existing same-project Drive references and MILESTONE nodes required at write. Link to existing ERP references requires no external OAuth/provider call. General schedule meetings remain allowed with no primary TASK.
- GET /projects/{projectId}/management/requests/{requestId} -> {requestId,resourceType,resourceId,rowVersion,status:APPLIED}; current actor/current membership only, 404 when not known. Receipt replay checks current mutation permission and feature flag before returning a previously applied outcome.
- GET /projects/{projectId}/management/history?resourceType=...&resourceId=...&page=0&limit=50 -> {entries:[{id,actorId,occurredAt,resourceType,resourceId,rowVersion,operation,before,after}],hasNext,page,limit}; scoped authorized read, limit<=100. Do not expose cross-project/audit identities or Google content.

## S3 exact API contract

- GET /projects/{projectId}/management/milestones/{milestoneId} -> MilestoneReview {projectId,milestoneId,criteria:Criterion[],decision:null|Decision,rowVersion,readiness:UNCONFIGURED|NOT_READY|PENDING|READY,canEditCriteria,canDecide}. Criterion {id,title,required:boolean,state:PENDING|MET|UNMET,supportingTaskIds:UUID[],fileReferenceIds:UUID[],missingEvidence:boolean}. Decision {state:READY|NOT_READY|EXCEPTION,reason:string,asOfDate:LocalDate,actorId:UUID,decidedAt:Instant,version:long}. Version0 empty for existing MILESTONE.
- PATCH same -> {criteria:[{id:UUID,title,required,state,supportingTaskIds,fileReferenceIds}],rowVersion,requestId}. Plan writer; criterion UUID stable, title1..500, max50 criteria/50 evidence each. Check same-project TASK/ref kinds and membership. Removing a criterion retains audit and prior decision history; later edits do not silently replace the stored decision.
- POST /projects/{projectId}/management/milestones/{milestoneId}/decisions -> {state,reason,asOfDate,rowVersion,requestId}; MANAGER only, reason1..1000. READY allowed only with configured required criteria all MET and valid evidence; EXCEPTION allowed with explicit reason despite incomplete criteria. Keep stored decision distinct from computed readiness and show when evidence changed after decision. No automatic readiness from completed-task counts. Readiness precedence: required UNMET/missing evidence -> NOT_READY; required PENDING -> PENDING; no required criteria -> UNCONFIGURED; otherwise READY.
- GET /projects/{projectId}/management/risks?timeZone=IANA -> {projectId,observations:[{id,type:OVERDUE|MISSING_DATES|BLOCKED|TIME_MISMATCH|MISSING_EVIDENCE,itemId,relatedIds,reason}],complete,observedCount,totalCount,asOfDate,timeZone,observedAt}. Use current stored state/deadline/dependencies/links only. A linked schedule local date outside TASK target interval or after deadline is TIME_MISMATCH observation, never an automatic edit. Missing evidence and manual health/decision remain separate. No critical-path, forecast recalculation, capacity score or invented business outcome.
